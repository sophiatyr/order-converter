# CSQ 客戶工作站

專供 Sports Kite 的 CSQ account 作業。主要流程為「匯入 PO → 訂單核對 → 文件輸出」。PDF、OCR、Excel 解析及 Excel 文件產生都在本機瀏覽器執行，不使用外部 API、雲端 AI 或 API 金鑰。

## ERP 產品資料

文件輸出頁按「帶入 ERP 產品資料」，使用本機 CSQ 產品快照對應精確款號，帶入 ERP 原品名、規格描述、工廠、工廠代碼、報價幣別與成本。ERP 原文若是英文會保留英文；不覆蓋客戶 USD 售價、顏色與尺碼件數。

產品快照首次已建立。ERP 有更新時，雙擊 `更新ERP產品資料.bat`，再回工作站按帶入。更新程式沿用 `C:\AI\sk-kpi\backend` 的連線設定、唯讀查詢及 CSQ 報價核對規則，僅取 ERP 中曾出現在 CSQ 訂單的產品。不呼叫 SK-KPI Web API，也不寫入 ERP；成功建立的快照可供離線作業。若產品從未出現在 CSQ 訂單，會顯示查無資料。

產品報價依精確款號帶入，每筆保留工廠、幣別、成本與單位。不同工廠／幣別／數量單位自動分成採購單，使用「選擇工廠採購單」切換預覽與匯出；Excel 檔名含工廠代碼、幣別與單位。客戶 P/I 保留完整訂單。多筆報價、未確認單位或缺成本的款號保留品名／規格並顯示提醒，暫不列入工廠採購單，不阻擋其他有效款號。ABCRA07 已由使用者確認一個 PO 數量等於一雙手套，可使用 PR 報價並標示 USD／雙，不乘二。其他 PR 品號仍需另行確認。更新失敗保留原快照。快照檔 `erp-products.json` 已排除 Git，內含公司資料。

此電腦的更新程式使用 Codex 附帶的 Python 3.12 與 SK-KPI `venv\Lib\site-packages` 套件。移至公司 Server 時需另設 Python 與 SK-KPI 路徑（後端路徑可用 `SK_KPI_BACKEND` 指定），不依賴 API 金鑰。開啟工作站不需要 Python；只有更新 ERP 快照需要公司 ERP 網路與 Python 環境。

## 啟動工作站

Windows 雙擊 `啟動訂單系統.bat`，開啟 http://localhost:8888。服務在背景執行，啟動視窗關閉後仍可使用；要停止時雙擊 `停止訂單系統.bat`。重新開機後需再次啟動，單獨開啟瀏覽器網址不會啟動服務。電腦需有 Node.js 24 或以上版本，日常使用不需安裝 npm 套件。

介面由 `scripts/local-server.mjs` 讀取 `offline_package/外貿成衣訂單轉換系統_單機離線完整包`。預設僅監聽 127.0.0.1:8888。

## 作業

- 訂單核對：下單公司、PO、S/C、日期、款色、客戶品號、尺碼件數及售價。工廠資料及交易條件在可展開區域。
- 文件輸出：英文 P/I、工廠採購單、數量明細表、早見表及原有 5 欄產品清單分別匯出。文件產生後保留下載連結，方便重試。
- 產品對照庫：維護中文品名、規格、工廠及成本。客戶售價與工廠美金成本分開，不互相覆蓋。
- ERP 多筆報價：按「帶入 ERP 產品資料」後，在「選擇工廠報價」逐款選定工廠、幣別、成本及日期，再按「套用所選報價」。同款所有顏色一起帶入；選擇隨訂單保存。ERP 快照更新後原選項不存在時，要求重新選擇；不自動挑最新價格。未確認款號暫不列入工廠採購單。
- 訂單備份：文件輸出頁可下載 JSON，在「匯入 PO」還原。也能讀取本機 SK-KPI 保存的 CSQ 解析 JSON，不呼叫 SK-KPI API。

保留原有瀏覽器訂單與產品對照庫；不再自動載入範例。請固定使用同一瀏覽器及 http://localhost:8888，變更網址、瀏覽器或電腦會使用不同儲存空間。

## SK-KPI 規則來源

已參考 `C:/AI/sk-kpi/backend/app/eoi/parsers/csq.py`、`csq_multiple.py`、`csq_fila.py`、`csq_ellesse.py`、`csq_medico.py`，以及編號和解析測試。

- CSQ account 的下單公司包含 CISALFA、FALIS、PREMIUM SPORTS、ITALIAN FITNESS、INTERSPORT、MEDICO，S/C 按各公司編號規則產生。
- CSQ 工廠交期提前一個日曆月，月底沒有同日則取前月月底；來源為 `backend/app/eoi/tgm/po_build.py` 的 `po_due_date`。
- `Multiplo` 表示下單倍數，不直接當成混碼裝袋配比。真正 Kit composition 需核對包數、包價與展開件數。
- 基本 Vendor PO 支援款色分列、換行款號、雙色碼、不同尺碼表與空白欄位保留。數量或金額不一致時提示核對。

CSQ Multiple Pack PDF 的 Kit composition 已依 SK-KPI 的規則移植為本機解析：主表 PZ 是包數，組成表提供每包尺碼配比，展開後以件數及件價作業，同時保留包數、包價、Kit code 與組成商品碼。會核對跨頁尺碼、包數×配比、組成合計、包價×包數、列印總包數與總金額；缺頁或矛盾資料會停止匯入。真實 PO 26OF029920／029925／029929／029930 已與 SK-KPI 逐款色交叉比對。其他品牌版型與逐尺碼售價仍須逐版驗證。

PDF 最多 50 頁／40 MB；掃描型文件仍需核對 OCR 文字。手寫或圖像註記不會自動套用為訂單修改。

## CSQ 參考成份與新增報表

`CSQ參考資料/訂單作業/工廠採購單` 的 Excel 檔在建置時轉成本機成份快照。以完整款號對應，優先比對相同客戶 PO；同款成份衝突時不猜測。採購單優先使用參考檔中文成份，無可確認資料時使用客人原始 PO 說明，不改動客戶 P/I。ERP 僅負責工廠與採購報價；成份來源另行對應。

資料夾新增或修改後，雙擊「更新CSQ參考資料.bat」，再按介面的「重新讀取參考成份」。原始參考檔只讀取，不修改，不隨程式提交；離線包附帶成份快照，日常使用不需要讀取 Excel 原檔或外部 API。

文件輸出提供 P/I、工廠採購單、數量明細及早見表四個預覽入口。預覽與下載使用相同 Excel 工作簿；數量明細每款一個工作表，可點選工作表切換。四個匯出選項維持同一列。

文件設定可選 Normal Pack 或 Multiple Pack，同步顯示在 P/I、採購單與早見表。CSQ 的 90LC 付款條件展開為 `100% AMOUNT BY USANCE L/C 90 DAYS.`。工廠名稱只顯示中文，ERP 原始名稱仍保留供資料比對。採購單預覽下方可替每個工廠／幣別／數量單位設定中文名稱、額外費用、是否支付訂金及比例；設定隨訂單及備份保存。額外費用逐項列在貨款小計與採購總額之間，不影響客戶售價、件數或其他工廠。訂金依含額外費用的採購總額計算，在付款條件顯示訂金與餘款。

文件版型從 `CSQ參考資料/訂單作業` 的「客人PI」、「工廠採購單」、「訂單資料-數量明細表」中含 PO副 的 Excel，以及 `CSQ-早見表-2026.xlsx` 讀取。優先匹配 S/C、PO、款號、包裝方式及工廠代號。P/I 保留參考表頭與簽章區，P/I 一般使用 10 欄，尺碼更多時才增加欄位；色碼一欄、色名兩欄、每個尺碼一欄，明細表按實際尺碼結束，不填滿整頁，款式間不加橫向分隔線。每款一張色碼、色名與尺碼數量表，面料移除重複品名及 Products composition 字樣；SHIPMENT 使用 BEFORE 加日期，TERMS 使用 FOB 出口地 BY SEA／AIR，預設 SEA。數量明細依實際款號建立獨立工作表，品號、品名分開，多種面料分行，僅列出實際顏色及有數量的尺碼，不保留範本多餘的空白數量列。採購單與早見表沿用參考版型，早見表補齊連續外框。

所有文件英文公司名稱使用 `SPORTS KITE INT'L CO., LTD.`，中文轉成繁體；英文使用 Calibri、中文使用微軟正黑體，混合文字依字元分別設定。P/I、採購單及早見表工作表名稱使用 P/I 號碼，數量明細使用款號。Normal Pack 的採購單顯示「單碼包裝」、明細顯示「單色單碼裝」；Multiple Pack 分別顯示「混碼包裝」、「單色混碼裝」。採購單金額總計使用對應幣別的中文大寫。預覽預設「完整寬度」，可切換 100%、125%、150%，並可向下瀏覽完整文件。每個預覽標示參考來源檔；預覽與匯出使用相同資料。

工廠採購依確認的 ERP 工廠、幣別及單位分檔；多工廠時，下載 ZIP，內含各工廠獨立 Excel。客戶 P/I 與早見表使用客戶 USD 售價。數量明細逐色、逐尺碼重新計算合計，包裝及尺碼／重量說明從參考檔帶入；成份無法確認時使用原始 PO 說明。

雙擊「更新CSQ參考資料.bat」同時更新文件版型快照，再於文件輸出按「重新讀取參考成份」。來源 Excel 只讀不改；版型快照留在本機，日常操作不用 Python 或外部 API。更新範本時需要 Python 的 openpyxl，舊 `.xls` 讀取器隨專案附帶。

## 開發及公司 Server

### 六個作業模組（初步架構）

- 訂單作業：訂單核對、訂單文件輸出合併在同一入口，保存多份 PO，以 PO 號碼更新而非重複新增。
- 訂單追蹤：本機參考進度與已匯入 PO 連結，維護各階段、面料測試並匯出 Bulk Status；匯出後由使用者提供客戶。
- 出貨作業：由 PO 建立分批出貨，填實際尺碼數量、箱數、淨重、毛重、材積；共用資料產生客戶／各工廠通知、Packing List + Weight、Invoice Excel。未確認文件標示草稿，累計出貨不可超過 PO 尺碼數量。
- 開發管理：新增與編輯款式、品牌、季節、打樣工廠、樣品進度及報價；開發款同步顯示於產品資料。
- 產品資料：整合 ERP、參考進度、已匯入訂單與開發紀錄，依品牌、季節、下單狀態篩選，補充備註。未查到下單不等於從未下單。
- 數據管理：已保存 PO 的季度下單分析，以及**已確認實際出貨**的 USD 業績；預計日期及出貨草稿不列入業績。完整工作站備份可下載與合併匯入。

`CSQ參考資料` 六個分類會建立本機檔案索引與欄位快照。訂單進度來源保留檔案、工作表及列號，不自動視為已完成；同一 PO 品號出現不同 S/C 或重複列時保留來源紀錄，避免錯誤合併。受保護／格式無法讀取的檔案顯示提醒。原始檔均保持不變。

成份來源已移至 `CSQ參考資料/訂單作業/工廠採購單`，仍相容舊資料夾。雙擊「更新CSQ參考資料.bat」會更新成份、參考進度及來源索引；再至「數據管理 → 資料來源與備份」重新讀取。

共用資料目前保存在固定瀏覽器網址的 `CSQ_WORKSPACE_V1`。舊的單份 PO 保留並帶入歷史清單；修改時沿用原有 `SK_SAVED_UPLOADED_ORDER`。完整工作站備份包含產品對照庫。這次為可操作的單機初版，客戶正式版型、樣品多次往返、報價版本、舊裝箱表自動匯入及多人共用可逐步優化。

```text
npm install
npm test
npm run lint
npm run build
```

建置會準備本機 PDF/OCR 語言檔與 worker，再更新 8888 使用的介面。修改程式後建置並重新整理頁面即可。

此版本同時提供離線工作站與 NAS 共用版。NAS 版使用個人登入、管理員／一般使用者、共用 SQLite、修改衝突保護與每日備份；ERP 保持唯讀快照，沒有即時雙向同步。離線作業資料與 NAS 資料不會自動同步。


CSQ 公司別 PDF 解析：FALIS（ELLESSE／BEAR）、PREMIUM SPORTS（FILA 單碼及 Kit composition 混碼）、MEDICO（SOLID／MULTI），直接上傳原始文字 PDF，全程本機運算。以 16 份原始 PO 驗證；其中 14 份逐項對照 SK-KPI，另外兩份 PREMIUM 欄位位移版型以原始 PDF 核對。件數、尺碼、包數、配比、款號小計與整單金額不符時停止匯入，不以參考號猜客戶 PO。MEDICO MULTI 單價是每件，1% 折扣及淨額保存於訂單來源欄位，沿用 SK-KPI 的原額／原件價匯入規則並提醒核對。掃描／純文字缺少欄位座標時不能套用公司別核對，請使用原始文字 PDF。
# 訂單追蹤雙模式

「內部訂單追蹤」沿用參考進度表全部 46 欄，包含 S/C 金額、工廠採購金額、換算值、利潤及收付款。原始合併金額保留群組範圍，未確認幣別或匯率時不重新計算利潤。

「客戶 Bulk Status」依客戶範本匯出 45 欄及 CONTROL 每週報告日期，排除內部財務及來源資訊。日期、階段狀態分開維護，面料測試必須 APPROVED 才能 READY，同款 Shipping Sample 只顯示一次。ETD Confirmed 需自行確認填入，不套用工廠交期。畫面預設 SS27，參考資料初始標示尚未出貨；預計船期不等於實際出貨。


## GitHub 程式版本與乾淨打包

儲存庫保存程式原始碼、相依套件鎖定檔、部署設定與測試程式。客戶 PO、ERP／進度快照、公司文件範本、測試原始文件、資料庫、備份、密碼與產生的程式包均排除 Git。原始公司資料仍保留在工作站或 NAS。

首次取得原始碼後，使用 Node.js 24 或以上：

```text
npm ci
npm run build:code
node scripts/package-local.mjs work/program-build
node scripts/local-server.mjs
```

程式碼建置不需私有參考資料；新工作站初始沒有公司訂單。既有訂單從完整工作站備份匯入，參考快照及正式文件範本由公司內部提供。`npm run build` 是內部完整建置流程，需要公司參考資料；`npm test` 的文件與整庫核對測試也需要排除 Git 的測試原始文件及快照。

```text
npm run lint
npm run pack:program
```

乾淨程式包輸出到 `releases/`，包含啟動檔及本機 PDF／OCR 資源，不包含公司作業資料。GitHub 的 Download ZIP 則提供可重建的原始碼。

NAS 部署使用 `deploy/nas`，建置與設定後僅在管理員指定時更新。更新正式程式前備份資料庫，保留 NAS `data/`；不要以離線測試資料覆蓋同事的進度。
